# Correcciones observadas, concurrencia y relojes
Las pruebas reales detectaron SQL ambiguo al reutilizar $2 para nombre TEXT y nombre_usuario VARCHAR, y faltaba resultado_validacion al generar un ticket de servicios. Se corrigieron ambos y se repitió la suite. La prueba de dos agentes requiere serializar las transacciones del adaptador embebido; en PostgreSQL también se mantiene bloqueo asesor y UPDATE condicional. El tiempo es calendario 24x7. Resolución descuenta pausas; primera atención mide creación a primer contacto. Reapertura conserva creación/primera atención y limpia resolución/cierre, sin borrar bitácora. P18 requiere Docker real y no puede declararse aprobado con PGlite.
